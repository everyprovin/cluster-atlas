# ClusterAtlas design and API

Approved brief: an original full synthetic-data GenLayer Project. Metric validation and canonical Kruskal minimum spanning tree, followed by threshold single-linkage components.

All fixture bytes are original MIT synthetic data with no PII. Bounds: 2..10 unique ASCII point IDs; complete square integer matrix, diagonal zero, off-diagonal 1..1000000, symmetric, all triangle inequalities. Unknown fields, duplicate JSON keys, duplicate IDs, malformed types (including bool-as-int), and oversized bodies (>32768 bytes) are rejected. Input URLs must be raw GitHub HTTPS URLs at an exact lowercase 40-hex commit and end in this project's own fixture namespace; source bytes must match SHA-256. The SDK response-size bound is post-download and does not claim network or redirect controls.

The zero-argument contract owns a TreeMap of JSON records. `lock_source(record_id, source_url, source_sha256)` captures independently fetched and validated source. `derive(record_id, expected_revision)` re-fetches and recomputes the complete result. `confirm(record_id, expected_revision)` independently re-fetches and recomputes once more, recording a SHA-256 certificate bound to chain, contract, owner, record, source and stage. `revoke(record_id, expected_revision, reason)` is irreversible and never needs the source. All writes require the original owner; expected revisions prevent stale writes; IDs cannot be reused. Views return actual dictionaries. `get_record(record_id)` returns state, result and capture binding. `get_configuration()` states protocol limits.

ConfigCohort additionally exposes `compare_assignment(record_id, assignment_json)` with strict full assignment, weighted flip cost and per-clause literal witnesses. SAT recommendations minimize cost then the false-before-true bit string in sorted ASCII ID order; UNSAT contains no model and cannot be confirmed. ClusterAtlas additionally exposes `components(record_id, threshold)` from the derived MST. Kruskal edges are sorted by (distance,leftID,rightID); each point belongs to one sorted component at any integer threshold 0..1000000.

Frontend: vanilla TypeScript/Vite and actual genlayer-js 2.0.0-rc.2. User supplies a real contract address and public source URL after publication. Local controls expose the algorithm using bundled synthetic fixtures. Chain reads and evidence are labeled separately. Actual writes use the injected wallet, verify chain/account, observe SDK finalized state where available and independently require raw FINALIZED/NORMAL/MAJORITY_AGREE, exact hash/sender/target/zero value and one leader SUCCESS before reading state; every available SDK field must agree. Unknown finality retains the transaction ID and blocks resubmission. No real infrastructure is modified. No external similarity, identity, road, funding, award or adoption claims are made.

Verification: actual v0.2.12 runner SDK tests with external HTTP fixtures mocked at the web boundary; independent validator acceptance and forgery rejection, state/ownership/revision failures, schema/resource boundaries, domain/wallet tests and TypeScript/Vite checks. Direct SDK tests are not live multi-validator consensus evidence. Independent review and public deployment are root responsibilities.
